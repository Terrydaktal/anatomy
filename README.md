# Skull Atlas

A local Three.js skull viewer, built in the same style as `~/Dev/brain`. The default is a detailed CT-derived skull with all 22 skull bones individually selectable. The app and model assets are bundled locally, so viewing needs no internet connection.

Bones and landmarks share one compact catalogue page with **29 bones** (22 skull bones, six auditory ossicles and the hyoid) and **737 landmark entries**. The CT view includes 698 native catalogue entries and 39 annotations on supplementary bones; 12 orbital entries are currently unlocated. Estimated regions are included by default and remain labelled. Six original CT cavity groups and the separate real micro-CT fragment remain available. The reference skull viewer has been removed; old reference links open the CT skull.

## Run

Install Git and uv and use a browser with WebGL support. With access to this repository:

```bash
git clone https://github.com/Terrydaktal/anatomy.git
cd anatomy
uv run python scripts/serve_viewer.py
```

Open **http://127.0.0.1:8010**. Use `--port 8011` to choose another port. The server binds to loopback by default. uv supplies Python 3.13 and the small Zstandard dependency; development and build dependencies are excluded from normal startup. The server automatically verifies and restores the bundled binary resources. No anatomy downloads, registration, JavaScript build, Blender or test browser installation is required. After the initial Python environment is installed, viewing works without internet access.

The same 29 bones, dental arches, 737 landmark entries and 150 prepared surface highlights are included in a fresh clone. One lossless `.zst` archive per binary keeps the repository smaller than storing native files and multiple compression copies. The archives total approximately **80.6 MB** and expand to approximately **203.7 MB** of ignored native assets. Ordinary Git is sufficient; Git LFS is not required. Model credits and the distinction between supplied boundaries, estimates and location guides are preserved.

To update, stop the server with **Ctrl+C**, then run:

```bash
git pull --ff-only
uv run python scripts/serve_viewer.py
```

Refresh the browser. Startup reuses unchanged assets and restores newer packaged versions after a pull. The environment, unpacked binaries, source caches and optional delivery copies are ignored, so running the viewer does not modify versioned files. Custom edits to unpacked geometry are preserved and reported rather than silently overwritten. Asset and code versions invalidate browser caches automatically.

The displayed model is `assets/skull-ct/surface.glb`, restored from [surface.glb.zst](assets/skull-ct/surface.glb.zst): **1,421,276 original CT triangles**, approximately **34.2 MB**, with 22 bone meshes and two dental-arch meshes. The original U3D per-corner surface normals and 4,064 normal-seam vertices have been recovered. Every triangle corner and face ID is identical to the native `skull.glb`, packaged as [skull.glb.zst](assets/skull-ct/skull.glb.zst), which remains the stable registration source. Both restored files open in Blender or another glTF-compatible application. The source selector offers the CT skull and the independent micro-CT bone fragment.

**Find a bone** sits above **Find a landmark**; each search filters its own list independently. **Landmarks** remains a catalogue category, organised into expandable types and then bones; shared landmarks appear once under **Multiple bones**. Searching opens matching branches and clearing that search restores their previous expansion. The bone search’s show/hide actions affect matching bones. Selecting a bone or landmark preserves bone visibility. Landmark checkboxes retain highlights and **Clear highlights** clears them. **About this model** collects anatomy coverage, sources, mesh resolution, landmark methods and accuracy limits, viewing instructions, credits and download information. The landmark search and its display settings sit below the bone groups, directly above the Landmarks category. Other display controls and the anatomical source selector sit at the bottom of the sidebar.

Landmark search text filters the catalogue only. Physical surface regions and nearby point guides remain hoverable and selectable on the model, including when the search has no results. Display settings, hidden bones, section cuts, occlusion and the point-guide hit radius still govern model interaction.

The orbital catalogue includes left/right **cranio-orbital foramina** (FIPAT TA2 482), searchable as **meningo-orbital**, **cranioorbital** or **sphenofrontal foramen**, alongside the existing zygomatic and anterior/posterior ethmoidal foramina. **All 12 orbital-foramen entries are currently unlocated on these skulls.** Their previous coordinates came from curated seeds and bone-shape projection, which did not identify a native opening and could point at intact bone. Active coordinates are now null; rejected candidate coordinates remain in `rejected_location` for provenance. These names remain searchable with source information, but have no spatial target, pointer hit, pin, painted region, Focus or Reveal action. Show all includes only the 725 entries with locations. Presence or absence is not inferred from the missing fit. Definitions follow [FIPAT TA2](https://cdn.dal.ca/content/dam/dalhousie/pdf/library/FIPAT/TA2/FIPAT-TA2-Part-2.pdf#page=5) and the [published anatomical study](https://pmc.ncbi.nlm.nih.gov/articles/PMC12551468/).

Clicking a landmark selects its highlight until another selection replaces it or the selection is closed. Only the landmark checkboxes retain multiple highlights independently of selection. `test_hover.py` verifies both catalogue and canvas clicks, clearing selection, retained checkbox highlights and the resulting canvas pixels.

## Anatomy coverage

| Group | CT skull |
| --- | --- |
| Cranial bones | All 8, individually selectable |
| Facial bones | All 14, individually selectable |
| Auditory ossicles | Six atlas ossicles registered to the CT temporal bones; estimated placement |
| Teeth | Original upper/lower dental-arch meshes |
| Associated bone | Atlas hyoid placed with a whole-skull similarity; estimated pose |
| Bony cavities | Frontal, maxillary and sphenoidal sinuses, ethmoidal and mastoid air cells, bony labyrinth cavities |
| Bone landmarks | Sutures, foramina, canals, meatuses, fissures, processes, articular surfaces, bone parts, ridges, notches, grooves, fossae and junctions; also ossicle/hyoid landmarks |

The CT model is Ohio University's **OUVC 10503** dry human skull, segmented by WitmerLab from a GE LightSpeed CT acquisition with 625 µm slice thickness. It retains every triangle in the highest-detail source export. Original surface normals replace the recalculated normals used by the earlier exporter, recovering the source shading around thin plates and authored seams. Export performs no subdivision, decimation, geometric smoothing or synthetic pore generation. This improves rendering fidelity; finer anatomical detail still requires a finer source scan, not a higher triangle count generated by subdivision.

The original inferior-turbinate resource contains two disconnected conchae, separated without changing their geometry. Teeth retain their original dental arches. The native CT GLB is unchanged. Seven supplementary atlas bones are packaged separately in `assets/skull-associated/bones.glb` (0.43 MB) and placed using `assets/skull-associated/manifest.json`. The complete reference skull is no longer loaded. Each ear chain receives one shared similarity transform derived from the local temporal-bone registration, preserving the chain relationships without bending individual ossicles. The hyoid uses whole-skull alignment and retains an atlas pose. These placements remain unvalidated cross-specimen estimates. The original atlas assets are retained for offline registration, source-face verification and attribution.

The CT file has an invalid zero unit-scale field. Its coordinates are uniformly scaled for display, and section coordinates are labeled **units**, not calibrated millimetres.

Landmarks highlight the **actual loaded bone surface**, using triangle clipping and the same polygons for drawing and picking, following the approach in `~/tasks/dental`. Every highlighted vertex stays on an original source triangle. Regions follow jaw movement, explosion, visibility, opacity and section cuts. Their colours do not alter the bone's normal colour setting. Source masks and fitted masks are identified in the selection card.

Pterygopalatine wall transfers repair enclosed native faces that the angle filter previously removed from the middle of a selected surface. Repairs require full coverage by the existing source-derived footprint and three neighbouring faces within the paint; open edges, source holes and the outer boundary are preserved. The fit report records every repaired native face. This removes a class of triangular gaps; the remaining source transfer and its anatomical boundaries are still estimated.

The CT viewer loads **precomputed highlights** before enabling its controls. The package contains all 737 catalogue records, including the 150 with supported surface geometry; location guides remain unpainted. It preserves the existing builder's exact positions, normals, native face IDs, picking lookup and provenance. Input SHA-256 identities cover the skull, supplementary bones, catalogue, source regions and generation code; the binary also has its own checksum. Missing, stale or damaged packages fall back to the existing module Web Worker. The original bone buffers remain intact. Pending fallback results obey the current hover, selection, estimate mode and reset state. Browsers without module-worker support retain the local builder.

Opaque highlights are batched by owning bone, with independent visibility, colour and exact native-face picking. Jaw motion, explosion and sections follow the same owner transforms. Transparent bones retain individual highlight rendering to preserve blending, and browsers without `WEBGL_multi_draw` use the individual path. Preparing the batch buffers during loading avoids a first-use upload when all regions are enabled. These changes preserve the current region boundaries and do not establish anatomical accuracy.

The active see-through preview blends its colour once per covered screen sample, retaining the original 0.5 opacity. Hidden triangles, front/back surfaces and different bone walls share a stencil mask, preventing overlapping layers from becoming a solid colour. The colour pass clears this mask each frame; normal depth testing, clipping and bone visibility still apply. `uv run --group dev python scripts/test_xray_blending.py` checks independent single-blend pixel values, overlapping meshes, closed surfaces and repeated frames, then verifies duplicate hidden surfaces leave real hovered sella, PPF and suture previews unchanged. Its `--mutant` replay must fail the same oracle.

The shipped binary archives also provide lossless **Zstandard level 19/window 23** HTTP delivery. Browsers without Zstandard support receive the restored native bytes. The optional compression script additionally generates **Brotli quality 11 and gzip level 6**, and compresses boundary data, JSON and viewer code. Originals remain available; compressed copies are verified against them. Content-versioned asset URLs receive one-year immutable browser caching. The HTML is revalidated, file edits immediately change the asset version, stale compressed copies are ignored, and ETags support conditional requests. Browser disk caching survives reloads and restarts unless cleared or evicted. Only generating the extra Brotli/gzip copies needs the optional `delivery` dependency group.

**Estimated regions are included by default**, including after Reset. The native reference atlas has 14 named source-authored feature selections; the CT specimen itself has none. The CT viewer also exposes ten original source face selections on the imported, unchanged ear-bone geometry. Those exact face identities do not validate the imported bones’ placement. Turning **Include estimated regions** off removes estimated regions and point guides while preserving enabled source selections. CT cavity surfaces remain independently available.

The reference atlas supplies **296 original surface components**: 282 joint domains and 14 articular domains. Named articular selections preserve the exact source-selected faces; condyle/head mappings cover the articular surface of that feature. Associations between source joint domains and named sutures are fitted using neighbouring bone surfaces. The source GLB checksum, vertex positions and triangle order are verified before those selections are exported. Native CT skull bones do not inherit these selections. The imported reference ear bones retain their own original face selections unchanged.

Most skull features have **no supplied anatomical region boundaries**. A catalogue coordinate now remains a **location guide only**, without a painted region. Generic ellipsoids, process profiles and micro-CT study strips are no longer used as anatomical boundaries. Source transfers, native opening fits, fitted suture contact bands and native bregma/lambda junction cues remain explicitly estimated. Optional pins retain approximate source-label, mirrored, curated and transferred locations. Highlights do not create missing holes or reconstruct thin canal walls, individual nutrient channels or accessory anatomy.

**Label positions are refined separately from painted boundaries.** All 1,435 native skull catalogue records retain their original study coordinates in `initial_placement`; 24 unlocated records (12 per specimen) have no active coordinate. Native author selections and accepted source regions anchor supported labels to real selected triangles. Other CT locations use individual bone-shape registration (trimmed similarity ICP and smooth nonrigid deformation), rather than bounding-box scaling. Surface normals, explicit inner/outer cortical exposure and forward/inverse diagnostics constrain the result. Empty-space guides remain in space; the browser no longer projects every guide onto an arbitrary wall. Six CT sinus/air-cell labels use the original same-specimen cavity geometry. Supported nasion/asterion junctions and sagittal contour extrema receive compact native point cues; asterion fits that exceed the 0.8-unit gap limit remain guides. Contour fits use the reference atlas orientation, matched to the CT bone; they are not Frankfort-plane calibration. Original manual seeds and all cross-specimen locations remain unvalidated estimates. A failed 4.5-unit projection or round-trip check is labelled **Uncertain location** in the locator.

**Explore mapped regions and points** under **Landmark display**, below the landmark search, filters to regions transferred from published BioDigital and UBC FossaFinder geometry. **Mapped regions and fitted points only** excludes location guides and contact-band estimates. The five BioDigital fossa types are mapped on both sides of the CT skull. Both maxillary alveolar processes and both bones of each zygomatic arch have accepted transfers. The UBC pterygopalatine transfer represents all three explicitly named source wall meshes: anterior on maxilla, posterior on sphenoid and medial on palatine, on both sides. Three-bone coverage does not establish complete or accurate anatomical boundaries. Partial bone coverage is labelled when a wall or owner is rejected. Other source landmarks are mapped where their catalogue identity and geometric fit pass the import checks. Missing assets, unmatched names and rejected transfers are recorded rather than silently substituted. A direct preview is `?study=mapped-regions`. Historical atlas transfers and their rejection reports remain available for offline source verification.

BioDigital transfers carry source selections through a registration of the complete source bone. Smooth native normals and cranial inner/outer compartments prevent correspondence from jumping across a thin bone. The inverse source label must agree with the forward projected author footprint; internal subdivision edges never define region borders. Original native triangles are clipped to that continuous field. Source-region proximity, footprint coverage, cranial side and cortical exposure checks reject unsupported transfers. Exposure rays detect buried faces that happen to have the expected normals. Mirrored reference bones use their supplied GLB normals to correct triangle winding without changing vertices or face IDs. The AO pass excludes coincident overlays from its normal/depth buffer to prevent speckling. Failed or obsolete unchecked transfers stay unpainted. These remain **cross-specimen estimates**, available when estimated regions are enabled. Native reference selections and fitted opening rims take precedence. Source identities, residuals, deformation checks, tolerances and target face IDs are recorded in `assets/landmark-regions/registered-regions.json`. Neither low residuals nor successful software checks establish anatomical accuracy.

The CT infraorbital and mental foramina use **geometry-fitted opening rims** on both sides. Their irregular contours come from depth views of this specimen, rather than circles around catalogue guide points. The resulting patches are clipped from native triangles and leave the holes open. These fits remain inferred region boundaries; their dimensions use uncalibrated CT display units.

The cavity overlays retain **189,964 original triangles** from the same OUVC 10503 source and coordinate system as the detailed skull. They outline spaces enclosed by bone; they are not additional solid bones or soft tissues. Showing cavities fades the surrounding bones, and **Cavity only** isolates the selected surface. Bilateral source groupings are retained, with their sides following the appropriate bones during illustrative explosion.

**Inside skull bone** opens an independent Halle micro-CT sample: a 17.5 × 17.5 mm skull-vault patch, native **0.125 mm** voxels, **776,546 triangles** and an approximately **18.6 MB** GLB. The real compact tables and porous interior remain one binary-bone surface. Outer-table, diploë and inner-table entries provide three optional location guides; no separate layer boundaries are supplied or painted. Rectangular cut faces are computational crop boundaries. The fragment is neither registered to OUVC nor a measured thickness map of that skull.

## Controls

- Drag to rotate, scroll to zoom and right-drag to pan. Touch supports rotation and two-finger zoom/pan.
- Hover to identify a visible surface; click it or a catalogue name to select it. A single tooltip follows the pointer and stays inside the canvas. The smallest exact hit is the main name; larger overlapping regions and the parent bone appear below it in a smaller vertical list.
- Right-click a bone on the skull for **Hide**. A right-drag still pans; Escape or clicking outside dismisses the menu. Each structure and group has a visibility checkbox. Group controls show partial visibility. Each bone also has a clickable colour dot that independently switches between its assigned colour and default ivory; changing appearance does not change visibility.
- The landmark section below the bones searches bone markings and filters by feature type or bone. Estimated regions are included initially; **Include estimated regions** can restrict the list to supplied selections. The CT view links directly to supplied reference selections. Hover or keyboard-focus a catalogue name for a temporary surface highlight; select it or check its box to retain the region. **Regions** controls the filtered set. **Pins** displays markers for checked, hovered and selected landmarks, off by default; **Names** adds projected labels. Pins appear only on visible surfaces. Broad regions use a visible point on their actual highlighted triangles when their fixed anchor is covered; entirely covered regions and guides have no pin. **See through bone** affects the active region preview, independently of pin visibility. Hidden bones, sections and view bounds also hide their markers. Entries without a located point have no marker. Surface hover discovers supported inactive regions on the hit bone even with a broad catalogue, preparing them in small batches. Exact surface hits are ordered by area, with the smallest first. Location-only guides also respond within 14 CSS pixels of their projected point, independently of zoom and the Pins/Names switches; hidden, clipped or occluded points do not respond. Guides remain unpainted, and clicking near a guide selects that entry. **Locate highlight** adds a ring, leader and name for the hovered or selected landmark. Supported areas use an anchor on their actual highlighted triangles; an unsupported feature is explicitly labelled **Approximate location · no surface boundary**. **See through bone** shows the active supported region through occluding bone, preserving the same surface geometry and respecting hidden bones and sections. Both aids are on initially and can be disabled independently. Pointer previews use the pointer tooltip and locator ring together; catalogue hover and selection retain the full locator caption. **Focus** frames the region with context; **Reveal** isolates its owning bones. Use exploded view or a section to inspect covered joint surfaces. **Restore skull view** restores the previous view after isolation. Reset clears regions, pins and cavity surfaces, restores all bones, and includes estimates again. On mobile, **Details and source** expands the landmark information while its action card stays compact.
- The same page provides independently toggleable sinus, air-cell and bony-labyrinth surfaces. Hiding the last cavity restores the previous opacity. The six ear bones and hyoid are part of the main CT skull catalogue; legacy ear/hyoid study links open their groups in that catalogue.
- Search by structure, group or side. Visibility actions apply to the matches while searching.
- The focus icon beside a row isolates and frames that structure. The selected structure's **Focus** button moves the camera while retaining context; **Isolate** hides other structures. **Restore view** restores the prior visibility, camera and section.
- Use the source selector to switch between the CT skull and the separate micro-CT bone fragment. Changing source reloads the viewer with that source's defaults.
- Use the exploded-view slider to translate bones apart and reveal the nasal cavity and cranial base. Bone dimensions, camera position and zoom remain unchanged; **Fit** explicitly reframes the wider arrangement when desired. Dental arches stay grouped. Jaw opening moves the mandible and lower dentition together around an illustrative hinge.
- Adjust bone colours, overall opacity and gloss, or a selected structure's colour and opacity.
- All bones start in default ivory. Hovering temporarily shows a bone's assigned colour, including different colours for left/right partners; moving away restores ivory. Bones with colour enabled keep their normal hover highlight. **Unique bone colours** switches all bones between their assigned colours and default ivory, and shows a mixed state when individual colour dots differ. **Reset all** returns bones to ivory. Depth shading reveals surface relief and cavities; it turns off during transparency to avoid false occlusion from transparent structures.
- Pin visibility checks try every simple anchor before sharing surface samples between regions. Pending pin work updates the overlay without redrawing the skull, uses a larger budget once rotation stops, and keeps visibility checks on the original highlighted surfaces. Catalogue hover reuses depth shading while the camera and bone geometry stay unchanged. Highlight shaders are prepared during loading to avoid first-hover compilation pauses. During a canvas drag, only the soft depth shading uses half the pixel dimensions; full shading returns on release. Bone triangles, highlight geometry, canvas resolution and picking stay at full detail throughout.
- More display controls provide sagittal, coronal and axial section planes, position and side reversal. Clipped surfaces remain open; no artificial internal bone or cut-face fill is added.
- Standard anatomical views, fit, reset-camera and PNG image download are at the top of the viewer.
- With the canvas focused: **F** fits visible anatomy, **R** resets the camera, **I** isolates the selected structure, **H** hides it, **Escape** clears selection and **/** focuses search. Input fields keep their normal keyboard behaviour.

Left and right always refer to the subject. Exploded positions and jaw motion are illustrative study transformations, not measured anatomy or joint kinematics.

The shipped archives and manifests are ready to view. The normal execution order is simply **serve → open in browser**. To rebuild, run **export → precompute → package → optional compression → verification → serve**:

```bash
uv run --group build python scripts/export_skull.py
uv run --group build python scripts/export_ct_skull.py
uv run --group build python scripts/export_cavities.py
uv run --group build python scripts/export_landmarks.py
uv run --group build python scripts/export_source_regions.py
uv run --group build python scripts/export_aperture_regions.py
OPENBLAS_NUM_THREADS=1 uv run --group build python scripts/refine_label_positions.py
uv run python scripts/sync_region_evidence.py
uv run --group build python scripts/export_microct.py
uv run --group dev python scripts/precompute_highlights.py
uv run python scripts/viewer_resources.py --package
uv run --group delivery python scripts/precompress_viewer_assets.py
uv run --group dev python scripts/test_viewer.py
uv run --group dev python scripts/test_anatomy.py
uv run --group dev python scripts/test_regions.py
uv run python scripts/test_region_evidence.py
uv run python scripts/serve_viewer.py
```

After changing source regions, label placements or highlight code, rebuild the highlights **after** those changes, then regenerate compression:

```bash
uv run --group dev python scripts/precompute_highlights.py
uv run python scripts/viewer_resources.py --package
uv run --group delivery python scripts/precompress_viewer_assets.py
```

`precompute_highlights.py` starts an isolated loopback server and headless hardware-rendered browser, runs the same worker builder used by the viewer, and writes `assets/landmark-highlights/manifest.json` and `highlights.bin`. The manifest records every input hash, each region's owner and source metadata, array types/offsets, bounds and the binary checksum. The binary stores Float32 positions/normals and Uint32 native-face and picking tables. Source-domain metadata is retained without loading the large fitting inputs in normal viewing. Unchanged valid outputs are reused; `--check` verifies freshness without rebuilding and `--force` rebuilds. Runtime skull, catalogue and code identities are checked against current files. When the two optional registered-region fitting inputs are absent, their recorded build identities are taken from the prepared package; the fitted surfaces themselves are still checksum-verified. Generic static hosting falls back to runtime construction and is not the documented launch path.

`viewer_resources.py --package` reads the six model GLBs and prepared highlight binary and writes their lossless `.zst` archives plus `assets/viewer-resources.json`. Current verified archives are reused. These archives, the highlight metadata, catalogue and source/credit manifests are versioned. The downloader caches the shared BioDigital skull catalogue, its region and bone buffers, object transforms, and pinned FossaFinder models/assembly metadata in ignored `data/source/mapped-regions/`. Cached files and available shipped source snapshot hashes are verified; `--offline` performs only integrity checks. It needs headless Chrome/Chromium and the dev dependency group. Original downloaded source files are not needed to run the viewer.

The exporter uses trimmed similarity ICP and regularized smooth bone deformations. Sampled Jacobian checks damp deformations that would fold. Selection membership is pulled back through the complete deformed source bone, with a 0.2 display-unit source tolerance. Barycentrically interpolated native GLB normals select compatible source faces; cranial radial signatures keep inner and outer surfaces separate. A native point has one value shared by incident triangles. Membership must also lie within **1.8 display units** of the forward projected author triangle union, without exposing its subdivision edges. Explicitly named inner/outer vault regions constrain both the original source footprint and native field. At least 95% of 500 expected native locations from the unprojected transported source footprint must be retained within `max(1, source-to-native projection p95)` units. An independent 1,000-sample check measures distance to the **transported author selection**, with a fixed p95 limit of **4.5 units**, irrespective of whole-bone mismatch. A candidate outside that limit can have its uncertain fringe clipped to the same source distance, then must pass all checks again. Opposite-cortex area may not exceed 1% for uniformly inner/outer cranial features. A separate first-hit ray check requires at least 95% of 500 source and native samples to reach their exposed cortex from seven cavity or exterior viewpoints. Its depth tolerance is 0.0002 times the owning bone's maximum span. This catches surfaces buried behind the cortical wall. None of these thresholds represents anatomical accuracy, and CT units are uncalibrated. Visible enclosed-hole checks run separately.

FossaFinder's `Anterior_Wall`, `Posterior_Wall`, `Medial_Wall` and `PPF_Region_v5` bone assembly use their full `Main.unity` transform chains relative to `Head`. Named walls constrain a shared smooth deformation and are matched only to the corresponding bone's facing surface. The one authored side is reflected for the opposite side and remains estimated. A p95 projection-distance gate of 3 display units applies to these walls; BioDigital footprint transfers use 4.5. Numerically unstable native faces narrower than 0.01 display units are excluded. CT units remain uncalibrated. The JSON records source/target identities, winding corrections, fit and coverage diagnostics and rejections; the binary records native triangles and their original face IDs. `--fossae-only` limits a rebuild to fossae, `--fossafinder-only` replaces the university transfers, and `--dataset reference --update` replaces one dataset while preserving the other. Repeatable `--feature ID` replaces selected BioDigital features in an existing package while preserving other features and university walls. `--output` selects a build directory.

Only natively fitted craniometric landmarks receive compact surface point cues; unfitted point labels remain location guides even when the external atlas supplies an area mask. `fit_point_landmarks.py` fits bregma and lambda independently on each skull to the exterior junction of their three native bones, using the catalogue location only to bound the search. It updates the catalogue in place and records the guide, fit, bone distances and specimen hash. The small display radius is a visual cue, not a region boundary or a measured uncertainty. `export_landmarks.py` also runs this step; to update an existing catalogue run `OPENBLAS_NUM_THREADS=1 uv run --group build python scripts/fit_point_landmarks.py` before syncing evidence.


`test_registered_regions.py` compares volume membership against an independent ray implementation, samples exported points against independently decoded GLB triangles, verifies hashes, all three PPF wall/bone pairs, deformations, facing-side containment and estimate status, and exercises CT filtering, picking, source labels and reset. ## Automatic region-source audit

Run `uv run python scripts/sync_region_evidence.py` to download pinned snapshots of Z-Anatomy's TA2 terminology and the official BodyParts3D 4.3 mesh inventory, then generate `assets/landmark-regions/evidence.json`. It needs no anatomy knowledge or extra dependencies. Source downloads are cached under ignored `data/source/region-evidence/`; later runs can use `--offline`. The downloader verifies each snapshot SHA-256 before parsing it. Bone models, source-selection binaries, fitted-rim binaries and specimen identities are checked on every audit.

The report covers every catalogue feature, identifies exact normalized name/alias matches to TA2, records available source selections and their scope, and separates native fits, contact bands, source transfers, rejected transfers unpainted location guides and unlocated names. A terminology entry never creates a boundary or upgrades a fit. Names are matched without fuzzy guesses; ambiguous matches remain separate candidates. Original cartilage face selections retain their source borders, while their named association remains inferred from material and location.

The BodyParts3D inventory is searched for exact English, synonym and Latin-name candidates. A separate atlas mesh is recorded as an **unregistered candidate**, not a supplied boundary on either viewer skull. Its scope, geometry and specimen registration still need verification by an import pipeline. Current snapshots provide one exact catalogue candidate: `FMA52891`, perpendicular plate of ethmoid, mesh `FJ6412`. This candidate is reported without being automatically painted onto a different specimen. The names and candidate inventory do not constitute independent anatomical ground truth.

Use `--require-source-boundaries` as an automatic coverage gate. It writes the report and exits **2** while any available catalogue feature lacks supplied boundaries; source/download corruption exits **1**. Currently the gate correctly fails: the reference provides **14 of 737** supplied feature selections, and the CT provides **0 of 698**. The four CT opening fits remain estimates. A generated report alone is a successful audit, not successful anatomical validation.

No per-feature independent anatomical ground truth is bundled, so `anatomical_accuracy_percent` remains **null**. Integrity checks, terminology matches, source coverage and anatomical accuracy are distinct. An automatic claim of 99% anatomical accuracy would require suitable independent labelled data and a defined spatial evaluation; the script does not invent that evidence.

`audit_landmarks.py` covers the **1,438 native catalogue records** (the 39 additional CT viewer placements on imported bones are checked by `test_associated_bones.py` and `test_catalogue_controls.py`): 698 CT, 737 reference and three micro-CT guides. It independently decodes original GLB triangles and checks every exported highlight vertex, native opening and named source face selection. Named internal/external cranial features also have independent radial-normal and exposed-cortex oracles. Exposure uses Embree from the build group, separate from the exporter's Blender BVH, with a different sampling seed. Containment and depth calculations use float64; ray geometry retains original GLB float32 precision. Queries are batched without reducing samples or changing tolerances. The browser builds every entry and checks that guides and withheld fits paint no area, while supported fits produce geometry only on their owners. UI journeys verify that the reference internal occipital crest is revealed, framed and pickable, and the failed CT transfer stays unpainted with an explicit reason. Requirements and tolerances live in `scripts/landmark-verification.json`; results and previews are written under `artifacts/verification/`. Browser failure still writes an incomplete report, rather than leaving an older successful result. `test_landmark_policy.py` verifies that the same audit oracle rejects an isolated mutant that reinstates a generic pterygoid-fossa patch.

Run the audit with both build and dev groups, as above. `--skip-browser` performs only geometry/inventory checks. `--package PATH.json --skip-browser` checks a preserved binary pair without changing viewer assets. The original package fails the side oracle for the CT internal occipital crest and inferior nuchal line; approximately 36% of its crest area was on the exterior. An intermediate package fixes that side error but still buries most of the CT crest behind the inner cortex. The exposure oracle rejects it and the CT internal occipital protuberance; both transfers are now withheld. The reference crest passes the software checks and remains estimated. The crest is an internal ridge descending to the foramen magnum ([Oxford Handbook of Head and Neck Anatomy, printed p. 19](https://api.pageplace.de/preview/DT0400.9780192664341_A42890947/preview-9780192664341_A42890947.pdf#page=37)). Wrong-side portions of the reference superior sagittal sinus groove are also withheld. `--require-supplied-boundaries` writes the audit and exits **2** while complete source-defined boundaries remain unavailable. Passing geometry and browser checks does not validate every anatomical boundary or guide coordinate.
